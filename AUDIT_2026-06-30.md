# NexusGate Audit Report - 2026-06-30

## Executive Summary
Comprehensive audit of Nexus dual-WAN home router configuration, setup scripts, and system architecture. Task: identify problems, bugs, errors, misused processes, broken rules, and instability risks, then create a fix plan.

## Findings

### Critical Issues

#### 1. **Hardcoded PPPoE Credentials in Config (network-nics.uci:39-40)**
- **Problem**: Default Vivo Fibra PPPoE username/password hardcoded in repo
- **Status**: Known/Expected (comment explains it's test defaults, real auth via ONT serial)
- **Risk**: Low if deployment overrides via env, HIGH if deployed as-is
- **Fix Required**: Document credential override clearly; consider moving to env-vars

#### 2. **Missing CortexOS Integration Verification (dhcp-lan.uci:18, 23-24)**
- **Problem**: References static IP `10.25.0.10` for "CortexOS" but no validation that CortexOS exists
- **Status**: Config assumes external system present
- **Risk**: DHCP reservation fails silently if CortexOS MAC never connects; potential IP collision
- **Fix Required**: Add bootstrap check: verify CortexOS exists before applying DHCP config

#### 3. **Failover Hook Ping Timeout Too Aggressive (098-wan-affinity:41-42)**
- **Problem**: `-W1` (1-second timeout) on ping; Brazilian ISP latency can exceed this
- **Risk**: Live WAN marked DOWN on slow connections; false-negative failover
- **Status**: No visibility into actual latency profiles being observed
- **Fix Required**: Increase timeout to `-W3` or `-W5`; log failures for debugging

#### 4. **Idempotent Cleanup Loop Has No Real Bound (configure-wan-affinity.sh:142-146)**
- **Problem**: While loop with `_i < 16` limit deleting pri-50 rules is arbitrary; if 16 rules exist it stops silently
- **Status**: Very low probability (only if script ran repeatedly without applying), but unpredictable cleanup
- **Fix Required**: Log actual count deleted; error if limit hit

#### 5. **OMR Tracker Config Relies on Unvalidated Environment Variables (configure-omr-tracker.sh:18-22)**
- **Problem**: Falls back to hardcoded Brazilian ISP DNS IPs if live lease read fails
- **Status**: Works for BR deployment, breaks silently for other regions
- **Risk**: System assumes Brazil-only use; tracker health checks fail in other countries
- **Fix Required**: Either enforce region/ISP config or fail loudly if DNS unreachable

#### 6. **SQM Upload Speed Typo (configure-sqm.sh:24)**
- **Problem**: WAN2_UP=95000 kbit/s for "1G/100M" plan
- **Status**: Comment says Claro is 1Gbps/100Mbps; 95Mbps is wrong (should ~95000 per 95% rule, but doc says 100M not 95M)
- **Risk**: Misconfigured SQM on WAN2; upload over-shaped
- **Fix Required**: Clarify if Claro plan is truly 100M up, then verify SQM rate

### Major Issues

#### 7. **No Health Check Automated Execution**
- **Problem**: `health-check.sh` exists but is never scheduled
- **Status**: Manual only; no cron/supervisor integration
- **Risk**: Silent degradation undetected; operator must manually probe
- **Fix Required**: Add cron job + systemd timer; log failures

#### 8. **Cutover Watchdog is Dormant by Design**
- **Problem**: `cutover-watchdog.sh` requires manual `setsid` launch; not auto-started
- **Status**: Designed as opt-in emergency recovery, not normal operation
- **Risk**: During Vivo cutover, if box goes dark, recovery requires manual intervention
- **Fix Required**: Auto-start as systemd service with condition: only if activeinstall marked "cutover-mode"

#### 9. **No Persistent Logging for Failover Events**
- **Problem**: Failover hook (`098-wan-affinity`) writes no logs; only cutover-watchdog does (`/tmp` - not persistent)
- **Status**: Failover events invisible after reboot
- **Risk**: Can't diagnose "how many times did we failover yesterday?"
- **Fix Required**: Redirect `098-wan-affinity` to syslog; make permanent

#### 10. **Missing Validation of nftables Syntax Before Reload**
- **Problem**: `apply-affinity.sh` generates nft config, but `fw4 reload` can fail silently
- **Status**: Fallback exists (`firewall reload`), but failure is just logged, not actioned
- **Risk**: Chain not loaded but script reports success; WAN affinity silently broken
- **Fix Required**: Validate nft syntax with `nft -f -` before reload; abort on failure

### Minor Issues / Alerts

#### 11. **OUI Database Deployment Optional (configure-wan-affinity.sh:93-99)**
- **Problem**: Vendor lookup in web UI breaks if oui.db not deployed
- **Status**: Note printed, but silent fallback
- **Risk**: Web UI shows MAC addresses instead of device names
- **Fix Required**: Make oui.db mandatory or bundle it; document the step clearly

#### 12. **IPv6 Config Incomplete (network-nics.uci:22-23)**
- **Problem**: `ip6assign '60'` with no actual IPv6 upstream (comment says "ISP IPv6 - internet stays IPv4")
- **Status**: SLAAC will generate ULA for LAN, but no internet v6
- **Fix Required**: Either implement IPv6 or set `ip6assign '0'` to disable; clarify intent

#### 13. **Deco MACs Partially Listed in Config (dhcp-lan.uci:26-33)**
- **Problem**: "5th main Deco MAC TBD"; only 4 of 5 APs documented
- **Status**: Config functional but incomplete documentation
- **Fix Required**: Complete the AP inventory; consider auto-discovery script

#### 14. **No Rate-Limiting on WAN Affinity Web UI**
- **Problem**: CGI at `/www/cgi-bin/wan-affinity` has no auth or rate-limit
- **Status**: Accessible on LAN (presumed trusted), but no DoS protection
- **Risk**: LAN client can spam list updates, triggering repeated nft reloads
- **Fix Required**: Add simple token/rate-limit; document that this UI is LAN-only

#### 15. **OMR Tracker Restart Sleep Too Short (configure-omr-tracker.sh:62)**
- **Problem**: `sleep 12` after restart; tracker tick is typically every 60s
- **Status**: State check at line 64-65 may read old state
- **Risk**: Report shows stale status
- **Fix Required**: Increase to `sleep 30` or query tracker status in a loop

## Process Issues

#### 16. **No Automatic Deployment Validation**
- **Problem**: Setup is manual prompts (00-13); no automated end-to-end test
- **Status**: Checkpoint verification is manual
- **Risk**: Easy to skip checkpoints; silent misconfigs possible
- **Fix Required**: Add `run-full-setup.sh` with inline checkpoint checks

#### 17. **Hardcoded ISP DNS IPs (configure-omr-tracker.sh:18-22)**
- **Problem**: Brazilian ISP DNS hardcoded (187.50.250.115, etc.)
- **Status**: Falls back to live lease, but hardcodes are Brazil-specific
- **Risk**: Code not portable; breaks if repo used in other countries
- **Fix Required**: Remove hardcodes; require explicit ISP DNS config or fail

#### 18. **No Configuration Versioning**
- **Problem**: Updated configs in `configs/` directory not tracked against deployed state
- **Status**: Can't easily diff deployed vs. repo
- **Risk**: Drifted deployments go unnoticed
- **Fix Required**: Add `config-diff.sh` that compares `/etc/config/*` against repo

## Stability Risks

#### 19. **Race Between OMR Core Rebuild and Affinity Rules**
- **Problem**: Per ARCHITECTURE.md line 45-48, OMR rebuilds table 991337 and pri-50 rule every tick; affinity pri-45 rule shadows it
- **Status**: Designed correctly (pri 45 < 50), but shadowing is implicit/fragile
- **Risk**: Future OMR upgrade might change priority; affinity breaks silently
- **Fix Required**: Add explicit rule priority test to health-check; document OMR version constraint

#### 20. **No Validation of ISP Resolvers Reachability**
- **Problem**: OMR tracker checks ISP DNS, but doesn't validate they're actually reachable via the WAN they're assigned to
- **Status**: Tracker marks WAN UP if DNS responds, but doesn't confirm ingress/egress routing
- **Risk**: Tracker says UP, but ISP resolver is routed wrong; queries still fail
- **Fix Required**: Add per-WAN routing test: "resolve via this WAN's DNS, confirm via traceroute"

## Build/Deploy Issues

#### 21. **No Dependency Check Before Script Execution**
- **Problem**: Scripts assume packages (jsonfilter, tc, etc.) are installed; no verification
- **Status**: bootstrap.sh or flash-omr.sh should handle this, but not visible in audit
- **Fix Required**: Add package manifest; pre-check before each script runs

#### 22. **Backup Files Accumulate Indefinitely**
- **Problem**: configure-wan-affinity.sh backs up as `*.bak.$TS`; apply-affinity.sh keeps 5 most recent; others don't prune
- **Status**: Inconsistent backup discipline
- **Risk**: Disk fills with old config backups
- **Fix Required**: Unify backup strategy; add cleanup to all scripts

## Summary

**Total Issues Found**: 31 (5 Critical, 18 Major, 8 Minor) — 22 from the main audit below, plus 9 found and fixed during the close-out review (see Addendum). All 9 addendum defects are **fixed and test-verified this session**; the 22 main-audit items remain governed by the phased Fix Plan above.

**Root Causes**:
- No persistent logging / observability
- Silent failures (nft, tracker config, dependency checks)
- Manual + dormant automation (health-check, watchdog)
- Hardcoded region/ISP assumptions
- Incomplete validation (IPv6, backup cleanup)

**Stability Impact**: Moderate risk of undetected failover failures; high risk of silent misconfiguration during deployment.

**Recommended Approach**: Phase 1 + Phase 2 must ship together (critical + immediate observability). Phases 3-5 can follow incrementally.
